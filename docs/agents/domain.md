# Domain docs

The engineering skills use a single-context layout for this repo.

## Before exploring

- Read root `CONTEXT.md` when it exists.
- Read ADRs in `docs/adr/` that relate to the work.

If these files do not exist, proceed. The domain-modeling skill creates them when terms or decisions are resolved.

## Layout

- `CONTEXT.md`: repo-wide glossary and domain context.
- `docs/adr/`: architectural decisions.

## Vocabulary and decisions

Use the terms defined in `CONTEXT.md` when naming concepts in issues, proposals, hypotheses, and tests. If a needed concept is missing, reconsider the term or note the gap for domain modeling.

If a proposed change conflicts with an ADR, call out the conflict explicitly.
